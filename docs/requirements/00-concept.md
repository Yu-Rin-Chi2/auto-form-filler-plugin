# 00. プロジェクトコンセプト

作成日: 2026-09-21
プロジェクト名（仮）: auto-form-filler-plugin
種別: Chrome 拡張（Manifest V3）
公開形態: OSS（https://github.com/Yu-Rin-Chi2/auto-form-filler-plugin）＋ Chrome Web Store、完全無料

## ビジョン

日本語の Web フォームに、自分の情報をワンクリックで正確に入力できる世界。
氏名・フリガナ・住所・電話番号を、会員登録でも問い合わせでも応募でも申請でも、二度と手で打たない。

## ミッション

Chrome 標準の自動入力が苦手とする日本語フォームの癖（フリガナ、姓名分割、電話番号 3 分割、郵便番号 2 分割、生年月日の 3 つの select、都道府県 select、ローマ字表記）を、判定特化 AI「Jev」の判断とローカルに保持したプロフィールで埋める。
**個人情報の値は端末の外に一切出さない。**

## 解決する課題

| 課題 | 現状 | 本拡張 |
|---|---|---|
| 同じ情報を何度も手入力する | サイトごとに 10〜20 項目を毎回入力 | ワンクリックで一括入力 |
| Chrome 標準のオートフィルが日本語フォームで効かない | `autocomplete` 属性のないフォーム、フリガナ、分割入力、`entry.NNN` のような無意味な name で無力 | ラベル・属性・周辺文脈から Jev が項目を判定（PoC で日本語 99%） |
| 個人用・会社用で入れる情報が違う | ブラウザのプロフィールは実質 1 つ | 複数プロフィールを切り替え |
| AI 系ツールは個人情報をサーバーに送る | クラウド型オートフィルは値がサーバーを経由 | 値はローカルのみ。Jev には「項目名」と「フィールドのメタデータ」だけ |

## ターゲットユーザー

**主**: 日本語の Web フォームを頻繁に入力する個人ユーザー

- EC サイトの会員登録・購入（住所・電話）
- 問い合わせ・資料請求・セミナー／イベント申込（氏名・会社・メール）
- 求人応募・各種サービス登録（生年月日・学歴以外の基本情報）
- 行政・自治体の申請フォーム（古い HTML、分割入力、ローマ字 name）

**前提となるリテラシー**: 特になし。API キーの取得・設定は不要で、インストール後すぐ使える（判定は開発者が運用する Cloudflare Workers のプロキシ経由で行う）。

**副**: フリーランス・小規模事業者で、個人と屋号／会社の情報を使い分ける人。

## 提供価値の優先順位

1. **手入力の手間をなくす** — 1 フォームあたり数十秒〜数分の削減
2. **日本語フォームで実際に動く** — 既存ツールが落とすフィールドを拾う
3. **複数プロフィールの切替** — 用途ごとに住所・メール・会社を使い分け
4. （前提条件として）**プライバシー** — 値はローカルのみ。訴求の主軸ではないが、破ってはならない制約

## 基本原則

### P1. 値はローカルにのみ存在する

- プロフィールの値は `chrome.storage.local` に保存する。`chrome.storage.sync`（Google サーバー経由）は使わない
- Jev に送るのは、プロフィールの**項目名と説明**（例: `family_name: "Family name in kanji（姓）"`）と、**フォームフィールドのメタデータ**（label / name / autocomplete / placeholder / type / section / select の選択肢の一部）だけ
- ユーザーが入力済みの値、プロフィールの値は、いかなる経路でも端末外へ送らない
- 例外なし。select の選択肢マッチングなど「値を送れば精度が上がる」処理も、MVP では採用しない

### P2. 送信しない

- フォームの値を埋めるだけで、submit ボタンのクリック・Enter 送信・ページ遷移は一切行わない
- 最後の確認と送信は必ず人間が行う

### P3. 扱わない情報を明確にする

- **カード情報**（番号・有効期限・CVV・名義）: Chrome 標準の支払い方法の自動入力に任せる。観測段階で除外し、Jev にも送らない、入力もしない
- **パスワード**: 同上。パスワードマネージャーの領分
- **ファイル入力・hidden・readonly・disabled**: 対象外

### P4. コードが制御し、Jev は判断だけ

- フォームの検出・フィールド列挙・値の解決・入力は決定的なコードが行う
- Jev は「このフィールドにはどの項目を入れるべきか」という分類だけを担う（1 フォーム = 1 リクエスト）
- Jev の回答は確信度で閾値判定し、低ければ入力しない。Jev に自律的な操作をさせない

### P5. ユーザー操作起点

- ポップアップのボタン、またはキーボードショートカットで明示的に起動する
- ページを開いただけで content script を常駐させない（`activeTab` + `scripting` で実行時注入）

## MVP の定義

初回の Web Store 公開に含めるもの:

- 複数プロフィールの作成・編集・削除・切替
- 対応項目: 姓・名（漢字／カナ／ローマ字）、氏名一体型、メール、電話、郵便番号、都道府県、市区町村、番地、建物名、住所一体型、国、会社名、部署名、生年月日、年齢、性別
- 分割入力への分配（電話 3 分割、郵便番号 2 分割、生年月日 3 select、姓名一体型 ⇄ 分割）
- select / radio の選択肢マッチング（コード側の正規化のみ）
- ポップアップからの実行、キーボードショートカットからの実行（前回のプロフィール）
- 入力結果のハイライトと件数サマリ
- プロフィールの JSON インポート／エクスポート
- 日本語・英語 UI

## スコープ外（MVP では Won't）

- カード情報の保存・入力
- パスワードの保存・入力
- フォームの自動送信
- ページ内バナーによる自動提案（content script 常駐）
- クラウド同期・アカウント機能
- Chrome 以外のブラウザの正式サポート（Chromium 系は動けば幸い）
- Jev に値を送るフォールバック（選択肢マッチング等）
- 課金・有料機能

## 成功の定義

| 指標 | 目標 |
|---|---|
| 対応付け精度（PoC フィクスチャ 86 フィールド） | 確信度 ≥ 0.7 で採用した項目の precision 99% 以上（PoC 実績 99〜100%） |
| 実サイトでの体感 | 代表的な日本語フォーム 20 種で、必須項目の 80% 以上が 1 クリックで埋まる |
| 所要時間 | ボタン押下から入力完了まで 1.5 秒以内（Jev 往復 ≈ 300ms） |
| コスト | 1 フォームあたり 0.05 円以下（PoC 実績 ≈ 0.025 円） |
| ストア審査 | 権限は `activeTab` / `scripting` / `storage` とプロキシ Worker のホストのみ。一発通過を目指す |
