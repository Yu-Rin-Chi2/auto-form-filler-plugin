# テストシナリオ: MVP（Must: F-01〜F-13）

> 作成日: 2026-09-21
> 対象機能: プロフィール管理、フォームのフィールド抽出、Jev による項目判定リクエスト、値の解決、入力実行、ポップアップ、オプション、i18n、オンボーディング（`docs/requirements/01-functional-requirements.md` F-01〜F-13）
> 対象範囲: Chrome 拡張（MV3）。ページ／ルーティングはなく、`popup.html` / `options.html` / content script（実行時注入）/ background service worker で構成
> 前提条件（共通）: 実 Jev API は呼ばない（モック必須）。`.env` は読み書きしない。`poc/` スクリプトは実行しない。フィールド抽出・値解決の純粋関数・DOM 操作を検証する層と、拡張全体を Playwright でロードして検証する層を分離する

## 0. 検証方針（層の定義）

| 層 | 対象 | ツール | 実行環境 | Jev |
|---|---|---|---|---|
| (a) 単体テスト | 値の解決・正規化・かな変換・分割・派生項目生成・リクエスト組み立て・レスポンス検証・プロフィールスキーマ検証などの純粋関数（`src/shared/`, `src/background/` の DOM/storage 非依存部分） | vitest | Node（jsdom 不要） | 呼ばない（関数呼び出しのみ） |
| (b) DOM 抽出・注入テスト | フィールド抽出、ラベル解決、radio グループ化、値注入、ハイライト（`src/content/`） | vitest + jsdom | jsdom | 呼ばない |
| (c) E2E テスト | 拡張全体（popup / options / background / content）を Chrome にロードしたブラウザ操作 | Playwright（`--load-extension`） | 実 Chromium | **モック**（`api.typesafe.ai` / `openrouter.ai` へのリクエストを route intercept し、フィクスチャごとに期待される `answers` を返す固定レスポンスを返却） |
| (d) 手動確認 | Web Store 審査観点、実サイトでの体感、ビジュアル・アクセシビリティ | 目視 + DevTools | 実 Chrome | 任意（実サイト体感のみ実 API 可、ユーザー自身の判断で実施） |

E2E（c）の共通前提: `npm run build` で `dist/` を生成し、`--load-extension=dist` で起動。Jev 呼び出しは Playwright の `browser_network_request` / route mock で横取りし、実際に `api.typesafe.ai` / `openrouter.ai` へ到達させない。以降の E2E シナリオの「前提」列は、特記のない限りこれに加えて記載する差分のみを示す。

## 付記: 実装確認が必要な仕様上の曖昧点

シナリオ設計中に見つかった、要件定義書だけでは一意に決まらない点。実装時に確定し、該当シナリオの期待結果を必要に応じて更新すること。

1. `FillResult` は `filled`/`skippedLowConfidence`/`noMatch`/`excluded` の 4 カウンタのみ定義されている。「未設定によるスキップ」「選択肢不一致」「`maxlength` 超過」「既存値による非上書き」「60 件超過」をどのカウンタに含めるか（またはカウンタを追加するか）が未確定。`E2E-FLOW-07`, `E2E-EDGE-03〜08` は実装後にカウント区分を確認して期待結果を具体化する
2. ポップアップの「詳細」に表示するフィールド単位の「状態」の具体的な文言・enum 値が未定義（`E2E-POPUP-08`）
3. `age`（うるう年 2/29 生まれの加齢タイミング）の扱いが要件上未規定（`UNIT-DERIVE-10`）。実装方針が決まり次第、期待結果を確定する
4. オンボーディング時の `chrome.runtime.onInstalled` による options 自動オープンは Playwright での自動検証が難しい場合がある（`E2E-ONBOARD-01`）。自動化できない場合は手動確認（6 章）に移す
